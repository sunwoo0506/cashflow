# 개발 회고

작업한 날짜별로 한 파일씩 쌓는다.

## 규칙

1. **파일 이름은 `YYYY-MM-DD.md`** — 하루에 여러 번 작업했으면 그 날짜 파일 아래로 **이어서** 쓴다.
2. **이미 쓴 회고는 고치지 않는다.** 그날의 판단이 그대로 남아 있어야 나중에 왜 그렇게 했는지 알 수 있다.
3. **이전 작업을 고쳤다면** 「이전 작업 수정 이력」 절에 *언제 한 것을 · 왜 고쳤는지* 를 남긴다.
4. 각 회고는 두 부분으로 쓴다.
   - **개발자용** — 무엇을 어떻게 했는지. 코드·구조·판단 근거
   - **쉽게 보기** — 도식과 그림 위주. 글은 최소로
