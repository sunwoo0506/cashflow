앞날(2026-09-07) 밤에 고정비 집행상태를 올린 뒤, 자정을 넘겨 들어온 신고를 처리한 기록이다.

## 1부 · 개발자용

### 1.1 확인 절차 — 코드가 아니라 데이터를 봤다

코드만 읽으면 「RLS 가 있으니 괜찮다」로 끝난다. 그건 확인이 아니다.

```
1) 익명 REST 로 각 테이블을 긁어 본다      → 새는 곳이 있으면 여기서 나온다
2) 회사·멤버십·회사별 건수를 센다           → 누가 어느 회사에 속했나
3) 행 id 가 회사끼리 겹치는지 센다          → 같은 행을 공유하나
4) RLS 미적용 · 정책 없는 테이블을 찾는다    → 구멍이 있나
```

#### 1) 익명 접근

```
receivables   []      fixed_costs  []
entities      []      expenses     []
organizations []
```

#### 2) 회사와 멤버

| 회사 | 소유자 | 채권 | 고정비 | 지출 | 법인 |
|---|---|---|---|---|---|
| 회사 ① | 계정 A | 106 | 9 | 55 | 법인A · 법인B |
| 회사 ② | 계정 B | 106 | 9 | 55 | 법인A · 법인B |
| 회사 ③ | 계정 C | 106 | 9 | 55 | 법인A · 법인B |

#### 3) 행이 겹치는가

```sql
select count(*) from (
  select id from receivables group by id having count(distinct org_id) > 1) x;
-- 0
```

채권 총 **318 = 106 × 3**. 법인 행도 회사마다 다른 uuid 다.

#### 4) 구멍

`public` 스키마에 **RLS 가 꺼진 테이블 0개 · 정책이 없는 테이블 0개.**

### 결론 — 새지 않았다. 다만 **똑같이 생겼다**

```
   보이는 것                        실제
   ─────────────                    ────────────────────────
   같은 화면                        회사 ①  ┌ 106건 (org_id=①)
   같은 법인명           ≠          회사 ②  ┌ 106건 (org_id=②)
   같은 금액                        회사 ③  ┌ 106건 (org_id=③)
                                    서로 겹치는 행: 0
```

샘플 데이터는 **고정 시드로 만든 같은 픽스처**다. 어느 회사에 넣어도 채권 106건·고정비 9건·
지출 55건·법인 「법인A·법인B」가 똑같이 나온다. 계정 셋이 각각 「샘플 적용」을 눌렀으니
세 화면이 픽셀 단위로 같아진다.

**이건 버그가 아니지만 결함이다.** 자료 유출과 구별이 안 되는 화면은 그 자체로 문제다.
「괜찮다」고 설명하는 것으로 끝내면 안 된다 — 화면이 스스로 말하게 만들어야 한다.

### 1.2 고친 것

#### `0006_sample_marker.sql`

```sql
alter table organizations add column if not exists sample_seeded_at timestamptz;
```

`null` 이면 실제 자료, 값이 있으면 샘플. 시딩할 때 켜고 초기화할 때 끈다.

권한은 함수로 열었다 — `organizations_update` 정책은 owner 만 허용하는데,
시딩은 담당자도 할 수 있어야 한다.

```sql
create or replace function fn_mark_sample(p_org uuid, p_on boolean) …
  if app_role(p_org) not in ('owner','manager','staff') then raise …
```

> **함정** · `create or replace view` 는 **뒤에만** 열을 붙일 수 있다.
> 중간에 끼우면 `42P16 cannot change name of view column`. 새 열을 맨 끝으로 옮겨 해결.

#### 화면

```
 ┌──────────────────────────────────────┐
 │ [가 회사 ▾]  [샘플 데이터]           │  ← 배지
 │ me@example.com · 가 회사             │  ← 누구로 · 어디를
 │ 기준 2026-09-08 · …                  │
 └──────────────────────────────────────┘
```

회사 이름은 이미 있었지만 **로그인 계정**이 없었다. 「내가 지금 누구지」에 답할 수 없으면
계정을 바꿨는지조차 확인이 안 된다.

#### 로그아웃 · 남은 쿠키

```ts
await supabase.auth.signOut();
response.cookies.delete(ORG_COOKIE_NAME);   // ← 없던 줄
```

세션만 지우고 「보고 있는 회사」 쿠키는 남기고 있었다.
`getCurrentOrg` 가 소속을 확인하므로 **악용은 안 되지만**, 로그아웃이 흔적을 남길 이유가 없다.

### 1.3 테스트 — 격리 규칙을 못 박았다

`test/tenancy.test.tsx` 6개. 실제 차단은 RLS 가 하지만, **그 앞단인 「어느 회사를 고르는가」**

## 2부 · 쉽게 보기

### 신고: 「다른 계정인데 똑같이 보여요」

당연히 의심할 상황이다. 그래서 **말로 답하지 않고 창고를 열어 세어 봤다.**

```
                창고 ①        창고 ②        창고 ③
                ┌────────┐   ┌────────┐   ┌────────┐
   계정 A ─열쇠─▶│ 106상자│   │ 106상자│   │ 106상자│
   계정 B ──────────열쇠──▶   │        │   │        │
   계정 C ─────────────────열쇠──▶      │   │        │
                └────────┘   └────────┘   └────────┘

   상자가 겹치는가?  →  0개.  창고 셋은 완전히 별개다.
```

**상자 안에 든 것이 같았을 뿐이다.** 셋 다 같은 「샘플 세트」를 주문했으니까.

```
   샘플 세트 = 정해진 내용물
   ┌───────────────────────────────┐
   │ 채권 106 · 고정비 9 · 지출 55 │
   │ 법인A · 법인B                 │  ← 항상 이 이름
   └───────────────────────────────┘
        │           │           │
        ▼           ▼           ▼
      창고①       창고②       창고③     ← 그래서 똑같이 보인다
```

### 열쇠 검사도 다시 해 봤다

```
   열쇠 없이 창고 열기       →  ✕  아무것도 안 나옴
   RLS 꺼진 창고 있나        →  0개
   자물쇠 없는 창고 있나     →  0개
```

### 그래도 고쳤다 — 「똑같아 보이는 것」이 문제니까

문제가 없다고 설명하는 것으로 끝내면, 다음에 **진짜로 샜을 때도 똑같이 보인다.**

```
   전                            후
   ┌──────────────┐             ┌────────────────────────────┐
   │ 가 회사   ▾  │             │ 가 회사 ▾   [샘플 데이터]  │
   │              │             │ me@example.com · 가 회사   │
   └──────────────┘             └────────────────────────────┘
      ▲                                  ▲
   누구로 로그인했는지            계정도 · 샘플인지도 보인다
   화면에 없었다
```

- **[샘플 데이터]** 배지 → 「똑같이 보이는 게 정상」임을 화면이 말한다
- **계정 이메일** → 계정을 바꿨는지 눈으로 확인된다
- 실제 자료를 넣으면 배지가 사라진다

### 로그아웃할 때 흔적 지우기

```
   전:  로그아웃 → 세션만 지움,  「보던 회사」 쪽지는 남음
   후:  로그아웃 → 세션 지움  +  쪽지도 버림
```

앞사람 쪽지를 다음 사람이 써도 **소속을 확인하니 열리진 않았다.**
그래도 남길 이유가 없어서 지운다.
